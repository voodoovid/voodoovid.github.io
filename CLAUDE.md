# voodoovid.github.io

Personal games site, published with GitHub Pages from `main` (root). Every push to `main` goes live automatically.

## Layout
- `index.html` is the home page with one card per game.
- Each game lives in its own folder (`hangman/`, `scareisdale/`, …) as a self-contained `index.html`.
- `flip-five/` (the Wordle-style game) carries its dictionary inside `index.html` as two long strings of five-letter words with no separators: `ANSWERS` (the words it picks from) and `EXTRA` (every other word accepted as a guess).
- `follow-chestnut/` (the Humanity-style crowd puzzle) keeps everything in `index.html`: the crowd simulation (`makeWorld`, `step`, no drawing) and the `LEVELS` array come first in the script, then drawing and UI. A level is a list of map strings (`#` hedge, space = hole, `.` floor, `S` door, `E` exit, `f` fish, `x` cracked floor, `b`/`c` plates that open gates `G`/`H`, `^ > v <` painted arrows) plus `dir`, `total`, `need` and `tools` ({ turn, jump, plank }). After changing a level, check in a browser console that `__fc.simulate(level, [])` loses and a known solution still wins with 3 stars (`[[y * width + x, "R"], …]`; commands U R D L J P). Levels are grouped into worlds by `WORLDS` (first level index, name) for the level picker. Each level plays one of eight synthesized music tracks in turn (`TRACKS` inside `Sound`); placing a command meows, and winning makes Chestnut grow and purr (`catGrow`).
- `flip-five/` plays on a 3D board by default: a three.js module at the end of the page draws split flaps over the board and mirrors the (invisible) page tiles, so game logic stays in the main script. Settings > **3D board** (saved in `flipfive.opts.view3d`) switches to the flat tiles; without WebGL it stays flat. Each landing flap calls `window.__flapClick` (the click sound). `flip-five-3d/` is only a redirect, for old bookmarks. three.js lives once in `lib/three.module.min.js` (r170) for any 3D game; keep it in `PAGES` in `sw.js` so it works offline.
- `ponchos-adventure/` plays in 3D by default with a **View: 3D / 2D** button (and V key), saved as `ponchos.view`. The game engine draws 2D with `draw()`; `frame()` calls `window.__draw3d` (a three.js module at the end of the page that reads the room from `window.__jk.g` each frame) while `window.__view3d` is true. Without WebGL it stays 2D. `ponchos-adventure-3d/` is only a redirect to it, for old bookmarks.
- `hangman/` plays in 3D by default with a **View: 3D / 2D** button next to the version label (and the 3 / 2 keys), saved as `hangman.view3d`. The page still draws the chalk on 2D canvases (`#gallows` for the gallows, `window.__figCanvas` for the rope and figure); a three.js module at the end of the page shows them as textures on a tilted board with a chalk tray, eraser and a real piece of chalk that travels to each stroke and draws it (`window.__chalk` is the tip, `window.__ink` changes on every redraw), chalk dust, and a figure that sways (swings after a loss). Without WebGL, or if the module fails to load, it stays 2D.
- `scareisdale/` (the Mario-style side-scroller, spooky rather than Halloween) has sixteen levels in the `LEVELS` array, four to a night (`levelIdx % 4` is the level number shown; `night` goes up every four levels and the game loops faster, with tougher bosses, after the citadel). Nights 3 and 4 are the harbor, mine, wax museum, cauldron, dark woods, sewers, clockworks and citadel. Each has a `build` function that places tiles and enemies with the helpers `ground`, `col`, `drum`, `row`, `en(type, x, y, opts)`, `fire(x, y, n)` (n = firebar length), `lava`, `ledge` and `spire` (map codes are listed above `buildLevel`), plus its `theme` (background in `BGS`, tiles in `TT`, exit building in `drawExit`), its music `track` (in `TRACKS`), the flagpole column `pole`, checkpoint column `mid` and an optional card hint `omen`. Every fourth level is a `castle` level (furnace, inferno, cauldron, citadel): lava (`L`; each theme's liquid look is in `LIQ`, e.g. bog, sea, sludge, brew), leaping `flameskull`s, long firebars, `lift`s (moving with `ax`/`ay`/`per`, or `fall: true` scaffolds), and a `boss` (`en('boss', x, y, { kind, hp, min, max })` on a bridge of `R` tiles, `updateBoss`/`drawBoss`). The four kinds each have their own attacks and weakness: `keeper` (fire breath; only fire hurts it), `golem` (shockwaves and lava rocks; fire-proof, stomp it while it has cooled after a slam), `witch` (flies, homing wisps, swoops; fire and stomps pass through, bonk the `=` perch under her from below, `bonkPerch`), `king` (teleports, shadow-orb fans, summons scarabs; only a kicked scarab shell hurts him, `shellHitsBoss`). Each gets faster at half health (`bossAngry`), and later laps add hp. Their projectiles are `BOSS_SHOTS`; instead of a flagpole a lever stands at the `pole` column and drops the bridge (`startFinish`/`updateFinish` phases lever, collapse, drop). Fire balance lives in `BURNABLE`/`TOUGH`/`updateFireball`: ghosts and flame skulls let fire through, `scarab` shells are fire-proof (stomp to a shell, kick it, `SHELL_PTS`), horses and ghouls take two, keepers take `hp`. Every level has a secret room: a level's `entries` maps a drum or pillar's left column to `{ room }`, `buildRoom(key)` lays the room out (24 columns, exit pillar at column 19), `ENTRIES[room]` says which main-level pillar you climb out of, and `ROOM_BGS` draws the newer rooms' backgrounds (`ROOM_TT` gives a room its own tiles). The ivy brick `V` in the graveyard grows a vine (it keeps growing during the climb); Pancake climbs it only when up is pressed at it (`atVine`, `startClimb`; ↑/W climb at a vine and jump elsewhere, the touch ▲ and controller up only climb) up to the wide `sky` room, whose pillars are `{ warp: levelIdx }` shortcuts to night 2 (`drawWarpSigns`). Secret drums and pillars carry a green marker. Hidden blocks are `H` (kibble) and `h` (golden mouse); `M` is a kibble brick; put them where Pancake can jump into them from below. Stomp runs past eight (`comboPts`) give extra lives, and finishing with the timer's last digit on 1, 3 or 6 gives that many fireworks. The exit building stands just past the pole; Pancake walks in, pokes her head out of the doorway and meows (`drawPeek`). Power-ups live in `powerUp`/`grow` (`P.form` is small, big, fire or wings; `P.star` is the catnip timer). Cmd-T / Ctrl-T opens a level select (`openLevelSelect`) with a **Show hidden items** switch (`showHidden`, saved as `scareisdale.showHidden`) that outlines and labels hidden blocks and item bricks (`HIDDEN_TAG`). `window.__scDebug` has `goLevel(i)`, `give(kind)`, `toPole()`, `bump(tx, ty)` and `shoot()` for testing.
- `fathom/` (the deep-sea word association game) keeps its prompts in `fathom/prompts.js` (`window.FATHOM_PROMPTS`, each `[prompt, "answer|answer/alias|…"]`, most common answer first; rank decides depth). Add new prompts at the end only: saved daily dives store prompt indexes. The scene is a canvas `Sea` module: landmarks sit at fixed depths (carnival 200 m, wreck and chalkboard 560 m, Flip Five board 780 m, whale, ghost, squid, vents, trench, treasure at 2,880 m) and Pancake, Chestnut and Poncho ride in the sub's portholes.
- `ponchos-pills/` (the Dr. Mario-style pill game) keeps everything in `index.html`: an 8×16 bottle in `g.grid` (a cell is `{ c, v, link }`: colour 0–2, `v` for a germ, `link` = side of its other pill half), germs from `makeGerms(level)`, and the turn cycle `toss` → `drop` → `lock` → `resolve` (clear runs of 4) → `finishPop` → `fallStep` until nothing moves. Poncho throws each pill from his paw; the lens shows one dancing germ per colour. The six music tracks in `TRACKS` (names in `TRACK_NAMES`) are original tunes; Music **Mix** picks one at random each level and moves on after three loops. A game in progress is saved as `ponchospills.save` (on each pill, pause and page hide), so the menu offers Continue. On a win Poncho grows and meows (`ponchoMeow`, deeper than Chestnut's). Original rules: pick level 0–20, the count stops at 24 (`MAX_LEVEL`); clearing level 5, 10, 15 or 20 on Med/Hi plays a celebration (`g.celebrate`, `drawCelebration`: Poncho rides a pill rocket, crowned at 20). The touch pad is two groups: turns for the left thumb, ◀ ▼ ▶ for the right. `window.__pp.clearGerms(n)` leaves only n germs for testing.
- Bluetooth / USB controllers: `lib/gamepad.js` (in `PAGES` in `sw.js`) reads the Gamepad API and turns buttons into the game's own key events (or calls functions), and moves a gold highlight between buttons while an overlay is open (A presses, B goes back). Poncho's Adventure, Poncho's Pills, Follow Chestnut (a mouse-style pointer that steps over visible tiles and slides onto the command panel at the board's edge; A on a tile opens a command picker drawn around it (d-pad places that arrow, A jump, X plank, B remove); LB/RB pick the command; the level picker opens on the level Play/Continue would start, via `menuFirst`) and Scareisdale call `GamePad.init({ map, menu, menuBack, help, onHelp })` right after their keyboard code. `help` lists the button mapping for the shared Controller settings screen (`GamePad.showHelp()`; each game places a `GamePad.settingsButton()` in its menu and toolbar, and Select opens it where the game maps nothing to Select); update it whenever a game's mapping changes. The Games menu (`index.html`) uses it too: the d-pad moves between game cards and A opens one; opening a controller game this way sets `sessionStorage` `gp.autostart`, and that game's `autoStart` (passed to `GamePad.init`) starts it without a tap. Add a new controller game to `PAD_GAMES` in `index.html` and give it an `autoStart`.
- To add a game: create its folder, add a card to `index.html`, and add the folder (plus any icons) to `PAGES` and its Google Fonts URL to `FONT_CSS` in `sw.js`.
- The site installs as one offline app ("Games" on the home screen): `manifest.webmanifest`, `icon-*.png` and `sw.js` at the root. Bump `CACHE` in `sw.js` whenever that file changes. Each game registers `../sw.js` and shows the shared gold **‹ Games** button: copy the `gamesPill` block (an `<a id="gamesPill">`, its `<style>` and `<script>`) from any game right after `<body>`, add the new folder name to its path check, and mark the game's top row with `data-pill-gap` so it shifts clear of the button. Keep the block identical in every game so the button looks and sits the same everywhere.

## Conventions
- **Every program must show a version number** on screen, e.g. a `const VERSION = "v1.0"` shown as a small label. Bump it on every change pushed (patch/minor as appropriate) and mention the new version in the commit message.
- Games must fit on an iPhone 17 Pro Max screen (about 440×800 visible in Safari) without scrolling, and also work on iPad and desktop.
- Sound must start from a user tap (iOS rule) and should work with the iPhone/iPad Silent switch on.
