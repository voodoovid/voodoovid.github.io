# voodoovid.github.io

Personal games site, published with GitHub Pages from `main` (root). Every push to `main` goes live automatically.

## Layout
- `index.html` is the home page with one card per game.
- Each game lives in its own folder (`hangman/`, `scareisdale/`, …) as a self-contained `index.html`.
- `flip-five/` (the Wordle-style game) carries its dictionary inside `index.html` as two long strings of five-letter words with no separators: `ANSWERS` (the words it picks from: Wordle's original answers plus every later answer the NYT has used; the hourly `wordle.yml` job runs `.github/scripts/add_wordle_answers.py`, which moves each new NYT answer from `EXTRA` into `ANSWERS` and rebuilds the single file, WITHOUT bumping `VERSION`: word-list updates are not game versions) and `EXTRA` (every other word accepted as a guess).
- `follow-chestnut/` (the Humanity-style crowd puzzle) keeps everything in `index.html`: the crowd simulation (`makeWorld`, `step`, no drawing) and the `LEVELS` array come first in the script, then drawing and UI. A level is a list of map strings (`#` hedge, space = hole, `.` floor, `S` door, `E` exit, `f` fish, `x` cracked floor, `b`/`c` plates that open gates `G`/`H`, `^ > v <` painted arrows) plus `dir`, `total`, `need` and `tools` ({ turn, jump, plank }). After changing a level, check in a browser console that `__fc.simulate(level, [])` loses and a known solution still wins with 3 stars (`[[y * width + x, "R"], …]`; commands U R D L J P). Levels are grouped into worlds by `WORLDS` (first level index, name) for the level picker. Each level plays one of eight synthesized music tracks in turn (`TRACKS` inside `Sound`); placing a command meows, and winning makes Chestnut grow and purr (`catGrow`).
- `flip-five/` plays on a 3D board by default: a three.js module at the end of the page draws split flaps over the board and mirrors the (invisible) page tiles, so game logic stays in the main script. Settings > **3D board** (saved in `flipfive.opts.view3d`) switches to the flat tiles; without WebGL it stays flat. Each landing flap calls `window.__flapClick` (the click sound). `flip-five-3d/` is only a redirect, for old bookmarks. three.js lives once in `lib/three.module.min.js` (r170) for any 3D game; keep it in `PAGES` in `sw.js` so it works offline.
- `flip-five-standalone.html` (site root) is Flip Five as one self-contained file for download, with three.js and the fonts embedded. It is GENERATED from `flip-five/index.html` by `.github/scripts/build_flip_five_standalone.py`; a GitHub Action (`.github/workflows/flip-five-standalone.yml`) rebuilds and commits it after every push that touches the game, `lib/three.module.min.js` or the script, so only ever edit `flip-five/index.html`. If you change anything the script patches (the three.js import line, the Google Fonts link, the `wordle.json` fetch), update the script too.
- `ponchos-adventure/` plays in 3D by default with a **View: 3D / 2D** button (and V key), saved as `ponchos.view`. The game engine draws 2D with `draw()`; `frame()` calls `window.__draw3d` (a three.js module at the end of the page that reads the room from `window.__jk.g` each frame) while `window.__view3d` is true. Without WebGL it stays 2D. `ponchos-adventure-3d/` is only a redirect to it, for old bookmarks. `Solver` (between the `Room solver` / `end solver` comments) searches a room's puzzle: Poncho's walks, framer pushes, hearts, tools and Medusa/Gol sight lines. With `{ strict: true }` it uses the exact rules (for designing rooms); without it, it gives the player every benefit of the doubt (moving monsters, eggs and spare tools count as solved), and `checkStuck()` runs that after every push, tool use or last shot, a slice per frame, and shows the **Stuck!** card only when the room truly can't be finished. Most rooms from 8 on are multi-step framer puzzles; after changing one, check in the console that `__jk.solve(i)` (room index) is `solved` with the expected `pushes`. Rooms that need eggs or moving monsters can't be checked strictly. Cleared rooms are saved as `ponchos.done.v4` (`MIGRATE` carried old progress over for rooms that kept their layout).
- `hangman/` plays in 3D by default with a **View: 3D / 2D** button next to the version label (and the 3 / 2 keys), saved as `hangman.view3d`. The page still draws the chalk on 2D canvases (`#gallows` for the gallows, `window.__figCanvas` for the rope and figure); a three.js module at the end of the page shows them as textures on a tilted board with a chalk tray, eraser and a real piece of chalk that travels to each stroke and draws it (`window.__chalk` is the tip, `window.__ink` changes on every redraw), chalk dust, and a figure that sways (swings after a loss). Without WebGL, or if the module fails to load, it stays 2D.
- `scareisdale/` (the Mario-style side-scroller, spooky rather than Halloween) has sixteen levels in the `LEVELS` array, four to a night (`levelIdx % 4` is the level number shown; `night` goes up every four levels and the game loops faster, with tougher bosses, after the citadel). Nights 3 and 4 are the harbor, mine, wax museum, cauldron, dark woods, sewers, clockworks and citadel. Each has a `build` function that places tiles and enemies with the helpers `ground`, `col`, `drum`, `row`, `en(type, x, y, opts)`, `fire(x, y, n)` (n = firebar length), `lava`, `ledge` and `spire` (map codes are listed above `buildLevel`), plus its `theme` (background in `BGS`, tiles in `TT`, exit building in `drawExit`), its music `track` (in `TRACKS`), the flagpole column `pole`, checkpoint column `mid` and an optional card hint `omen`. Every fourth level is a `castle` level (furnace, inferno, cauldron, citadel): lava (`L`; each theme's liquid look is in `LIQ`, e.g. bog, sea, sludge, brew), leaping `flameskull`s, long firebars, `lift`s (moving with `ax`/`ay`/`per`, or `fall: true` scaffolds), and a `boss` (`en('boss', x, y, { kind, hp, min, max })` on a bridge of `R` tiles, `updateBoss`/`drawBoss`). The four kinds each have their own attacks and weakness: `keeper` (fire breath; only fire hurts it), `golem` (shockwaves and lava rocks; fire-proof, stomp it while it has cooled after a slam), `witch` (flies, homing wisps, swoops; fire and stomps pass through, bonk the `=` perch under her from below, `bonkPerch`), `king` (teleports, shadow-orb fans, summons scarabs; only a kicked scarab shell hurts him, `shellHitsBoss`). Each gets faster at half health (`bossAngry`), and later laps add hp. Their projectiles are `BOSS_SHOTS`; instead of a flagpole a lever stands at the `pole` column and drops the bridge (`startFinish`/`updateFinish` phases lever, collapse, drop). Fire balance lives in `BURNABLE`/`TOUGH`/`updateFireball`: ghosts and flame skulls let fire through, `scarab` shells are fire-proof (stomp to a shell, kick it, `SHELL_PTS`), horses and ghouls take two, keepers take `hp`. Nights 3 and 4 add their own monsters: `eel` (waits in a liquid gap, leaps across it: `en('eel', x, 14, { span })`, span = gap width − 1), `crow` (perches, dives at Pancake), `cart` (mine cart, rolls between walls and turns at edges, iron), `wax` (wax figure, moves only while Pancake moves, fire melts it), `toad` (hops, tongue lashes out in front), `wolf` (prowls, crouches, pounces; takes two), `rat` (fast and low), `cog` (rolling gear: stomping it hurts, iron; only a kicked shell or catnip stops it) and `knight` (empty armor, shield blocks fire from the front, takes two, turns at edges). Iron monsters are in `IRON`; `edgeAhead` is the turn-at-the-edge check. Every level has a secret room: a level's `entries` maps a drum or pillar's left column to `{ room }`, `buildRoom(key)` lays the room out (24 columns, exit pillar at column 19), `ENTRIES[room]` says which main-level pillar you climb out of, and `ROOM_BGS` draws the newer rooms' backgrounds (`ROOM_TT` gives a room its own tiles). The ivy brick `V` in the graveyard grows a vine (it keeps growing during the climb); Pancake climbs it only when up is pressed at it (`atVine`, `startClimb`; ↑/W climb at a vine and jump elsewhere, the touch ▲ and controller up only climb) up to the wide `sky` room, whose pillars are `{ warp: levelIdx }` shortcuts to night 2 (`drawWarpSigns`). Secret drums and pillars look exactly like ordinary ones; nothing in the game points to a secret room. More secrets: a level's `left` names a room you reach by holding left against the very start of the level (nothing hints at it: explorers find it themselves); `above: { x0, x1, room }` is a room you reach by jumping up off the top of the screen between those columns, from a high ledge (Midway, Harbor, Woods); `enterSecret(room)` fades into either. Rooms in `NOOKS` are 34 columns wide with a false wall `F` (drawn as wall, not solid) at column 23, so past the exit pillar there's a hidden nook the camera only shows once you walk through; when the room's `ENTRIES` also has a `{ room }` at column 30, its nook holds a pillar to a room deeper still (tomb → ossuary, gallery → studio, cistern → catacomb). `OPEN_ROOMS` have no roof. Castle levels put an iron gate `X` (solid, `drawGate`) in the column before the lever; it rises (`openGate`/`updateGate`) only once the boss is beaten, so the boss can't be skipped. The keeper can also be hurt by a ground pound on its head. Hidden blocks are `H` (kibble) and `h` (golden mouse); `M` is a kibble brick; put them where Pancake can jump into them from below. Stomp runs past eight (`comboPts`) give extra lives, and finishing with the timer's last digit on 1, 3 or 6 gives that many fireworks. The exit building stands just past the pole; Pancake walks in, pokes her head out of the doorway and meows (`drawPeek`). The meow is a recording, `scareisdale/meow.mp3` (loaded in `Snd.init` as `meowBuf`; the synth in `Snd.meow` only plays until it loads). Power-ups live in `powerUp`/`grow` (`P.form` is small, big, fire or wings; `P.star` is the catnip timer). Cmd-T / Ctrl-T opens a level select (`openLevelSelect`) with a **Show hidden items** switch (`showHidden`, saved as `scareisdale.showHidden`) that outlines and labels hidden blocks and item bricks (`HIDDEN_TAG`) and tags every secret drum or pillar with where it leads, or which room you climb out of it from (`pathTagText`, `drawPathTag`). The level select also has a **Bosses** row (Furnace, Inferno, Cauldron, Citadel) that starts that castle level at its save point just before the boss (`pickLevel(i, true)` sets `checkpoint` to the level's `mid`). `window.__scDebug` has `goLevel(i)`, `give(kind)`, `toPole()`, `bump(tx, ty)` and `shoot()` for testing.
- `fathom/` (the deep-sea word association game) keeps its prompts in `fathom/prompts.js` (`window.FATHOM_PROMPTS`, each `[prompt, "answer|answer/alias|…"]`, most common answer first; rank decides depth). Add new prompts at the end only: saved daily dives store prompt indexes. A GitHub Action (`.github/workflows/fathom-daily.yml`, script `.github/scripts/fathom_daily.py`, ~200 Wikidata categories in `CATEGORIES`) runs every Monday and writes `fathom/daily/YYYY-MM-DD.json` for yesterday through 14 days ahead (the daily dive loads its day's file, falling back to the built-in prompts), and keeps `fathom/freeplay.json` (every Wikidata category with enough answers) for Free dives, which draw from it plus the built-in prompts; it is separate from the daily files so free play never shows a coming day. Editing the script re-checks every category (`fathom/daily/check.txt`) and rebuilds `freeplay.json`; add `[make days]` to that commit message to make the days at once. The scene is a canvas `Sea` module: landmarks sit at fixed depths (carnival 200 m, wreck and chalkboard 560 m, Flip Five board 780 m, whale, ghost, squid, vents, trench, treasure at 2,880 m) and Pancake, Chestnut and Poncho ride in the sub's portholes.
- `ponchos-pills/` (the Dr. Mario-style pill game) keeps everything in `index.html`: an 8×16 bottle in `g.grid` (a cell is `{ c, v, link }`: colour 0–2, `v` for a germ, `link` = side of its other pill half), germs from `makeGerms(level)`, and the turn cycle `toss` → `drop` → `lock` → `resolve` (clear runs of 4) → `finishPop` → `fallStep` until nothing moves. Poncho throws each pill from his paw; the lens shows one dancing germ per colour. The six music tracks in `TRACKS` (names in `TRACK_NAMES`) are original tunes; Music **Mix** picks one at random each level and moves on after three loops. A game in progress is saved as `ponchospills.save` (on each pill, pause and page hide), so the menu offers Continue. On a win Poncho grows and meows (`ponchoMeow`, deeper than Chestnut's). Original rules: pick level 0–20, the count stops at 24 (`MAX_LEVEL`); clearing level 5, 10, 15 or 20 on Med/Hi plays a celebration (`g.celebrate`, `drawCelebration`: Poncho rides a pill rocket, crowned at 20). The touch pad is two groups: turns for the left thumb, ◀ ▼ ▶ for the right. `window.__pp.clearGerms(n)` leaves only n germs for testing.
- `mind-the-gap/` (the Rush Hour-style sliding puzzle, London Underground themed; it was Ant Jam, and `ant-jam/` is now only a redirect for old bookmarks) keeps everything in `index.html`. `LEVELS` holds 40 original puzzles (10 per fare zone, shown easiest first: `TIERS` Zone 4, 3, 2, 1), each `{ b, min }`: `b` is the 6x6 board read row by row (`.` empty, `A` Rosie, the vintage red tube train, on row 3, other letters trains: 2 long is a single tube car, 3 long a two-car train), `min` the fewest moves (a move = sliding one train any distance; consecutive slides of the same train merge into one). They were made by a solver, not copied from any published puzzle set. `solve()` is a BFS used for Hint; after changing levels check in the console that `__aj.solveAll()` returns `[]`. Saved keys still use the old `antjam.` prefix so progress carried over: `antjam.best` (stars per level), `antjam.level`, `antjam.view` (3D/2D, the **3D/2D** button and V), `antjam.sound`, `antjam.music`. Every piece is tube stock; `trainOf` gives each one a London Underground line's colour from `LINES` (TfL colours via `lineLivery`, which derives darker doors and roof; Central red is left out so only Rosie, `LIVERY.rosie`, is red), shared by both views (`window.__tsTrain`). The user dislikes the old yellow battery locos, so don't bring back locos or non-tube stock. In landscape at 700px wide and up (iPad, iPhone, desktop) the board fills the height and the level, moves and tool buttons sit in a column on the right (CSS grid in the landscape `@media` block). The 3D view (three.js module at the end; reads `window.__aj` each frame and answers `window.__pick3d` for dragging) looks down on a depot with a slight tilt towards the player (`TILT`, 16°; `size()` fits it by projecting the scene's corners, so keep `bounds` covering the depot and the road): four-rail track built per level from `linesOf` (current rails gapped where lines cross), long, narrow trains with painted skins (`carTexture`, mapped round the body by angle so the doors and windows show on the curved shoulders from above; cab faces from `cabFront`) on rounded bodies (`bodyGeo`), turning bogie wheels and shoe sparks, a platform edge reading MIND THE GAP, the station notice SEE IT. SAY IT. SORTED. painted on the bottom walkway (in the 2D view too), and a road bridge over the tunnel with a red bus, a black cab and a phone box. The signal by the tunnel is green when `pathClear()`. The road on the right has live traffic, simulated in the main script (`traffic`, `trafficStep`, ROAD lanes in 3D units: lane 0 up the screen at x 4.43, lane 1 down at x 4.95, UK keep-left) and drawn by both views (`drawTraffic2d`; 3D `makeVehicle` builds each kind once and merges it into one mesh per material, `syncTraffic`, clipped at the road ends): cars, black cabs, white vans and the red 205 bus, following each other, stopping for people at the zebra (Belisha beacons flash), strollers on the pavement. Every 205 starts smoking just past the zebra, pulls in at the bus stop with hazards flashing and sits for 2.5–3.5 minutes (`wait`), then leaves; no new 205 for 40–80 s after (`busCool`). While it's parked, cars take turns pulling out round it and oncoming traffic holds back (`ourTurn` cycle). Canvas textures are supersampled (`tex(w, h, paint, srgb, ss)`), shadows 4096, pixel ratio up to 3. Train sounds are REAL recordings in `mind-the-gap/sfx/` (the user rejected synthesized train noises and any rising motor tone; don't bring them back): `move1-4` (a slide), `bump`, `depart` (Rosie pulling out on a win, panning toward the tunnel), `pass1-4` (another train going by every 18–36 s, `Snd.ambient`; one soon after each new level, `Snd.soon`), cut from ESC-50 train clips (CC BY-NC 3.0, credited in the guide). Station announcements `pa-*.mp3` (see it say it sorted, line welcomes, Central line delays, doors, gap, belongings, next train) were voiced offline with Kokoro TTS (British voices) and run through a loudspeaker effect (telephone band, overdriven horn, delayed speakers down the platform, tiled-station reverb); one plays every 40–75 s (`nextPa`, never the same twice running). `pa-mindthegap` plays on Play and when the title sign is tapped (`mindTheGap`, device voice only as a fallback); `pa-sorted-short` plays over Rosie's departure on a win (0.1 s after the win, not later). The real TfL recordings can't be fetched here, so the Kokoro voices stay. Cmd-T / Ctrl-T opens a hidden **Station announcements** menu (`SAYINGS`, `sayOpen`): every `pa-*` clip as a row, tap to hear it, tap again to stop; add any new clip to `SAYINGS` as well as `SFX`. `pa-mindthegap` was regenerated with Kokoro `bf_emma` (speed 0.9) because the user said the old one didn't sound female; the device-voice fallback (`announce`) now prefers a female en-GB voice. `pa-sorted-short` and `pa-sorted` are only trimmed and slowed to 0.92x (the 0.78x version with EQ and compression sounded slow and mechanical). `pa-delay205` ("Due to unforeseen circumstances, the 205 to Marble Arch has been delayed indefinitely", Kokoro bf_emma at speed 0.85 through a rough loudspeaker chain; made with onnxruntime and hand-written phonemes, never listened to) is one of the random `INFO_PA` announcements. The 205's smoke is deliberately faint and sparse (v2.9). The 205 is an all-red double-decker (roof included, same red as the body, digits white with a black outline) in the style of Stagecoach's Enviro400s, white-on-black blind reading Paddington 205. To redo the voices: Kokoro TTS (onnx, GitHub release model files) with espeak-ng en-gb phonemes, then the loudspeaker chain; keep them clear (light drive, modest reverb), as the user asked. `loadSfx` fetches them after the first tap, `playBuf` plays them, `duck` dips the music under them. Add new files to `SFX` and to `PAGES` in `sw.js`. The music is trip-hop: three original pieces in `TRACKS` (chords per half bar; `compose()` writes each sparse melody from the chords when the page loads), one per level in turn, with a broken beat (`kick`, `snare`, `hat`, patterns in `KICKS`), `sub` bass, Rhodes chords (`ep`) through a tremolo (`tremOut`), the melody through a tape echo (`echoOut`), vinyl crackle (`startCrackle`) and a big dark room reverb (`musicOut`); Play speaks "Mind the gap." with the device's British voice when it has one (`announce`). The user's guide is the `#ovHelp` card (the **?** button, **How to play** on the title card, or the ? key); update it whenever controls or rules change.
- Bluetooth / USB controllers: `lib/gamepad.js` (in `PAGES` in `sw.js`) reads the Gamepad API and turns buttons into the game's own key events (or calls functions), and moves a gold highlight between buttons while an overlay is open (A presses, B goes back). Poncho's Adventure, Poncho's Pills, Mind The Gap, Follow Chestnut (a mouse-style pointer that steps over visible tiles and slides onto the command panel at the board's edge; A on a tile opens a command picker drawn around it (d-pad places that arrow, A jump, X plank, B remove); LB/RB pick the command; the level picker opens on the level Play/Continue would start, via `menuFirst`) and Scareisdale call `GamePad.init({ map, menu, menuBack, help, onHelp })` right after their keyboard code. `help` lists the button mapping for the shared Controller settings screen (`GamePad.showHelp()`; each game places a `GamePad.settingsButton()` in its menu and toolbar, and Select opens it where the game maps nothing to Select); update it whenever a game's mapping changes. The Games menu (`index.html`) uses it too: the d-pad moves between game cards and A opens one; opening a controller game this way sets `sessionStorage` `gp.autostart`, and that game's `autoStart` (passed to `GamePad.init`) starts it without a tap. Add a new controller game to `PAD_GAMES` in `index.html` and give it an `autoStart`. The library shows one round 🎮 chip (`#gpChip`) right beside the **‹ Games** button (in its place on the Games menu): outlined and pulsing while it waits for a controller (a tap wakes the page in the home-screen app), solid gold with a green dot once connected (a tap opens Controller settings). The `gamesPill` block's `fit` (exposed as `window.__pillFit`) moves `data-pill-gap` rows clear of both, so no other controller notice should float over a game.
- To add a game: create its folder, add a card to `index.html`, and add the folder (plus any icons) to `PAGES` and its Google Fonts URL to `FONT_CSS` in `sw.js`.
- The site installs as one offline app ("Games" on the home screen): `manifest.webmanifest`, `icon-*.png` and `sw.js` at the root. Bump `CACHE` in `sw.js` whenever that file changes. Each game registers `../sw.js` and shows the shared gold **‹ Games** button: copy the `gamesPill` block (an `<a id="gamesPill">`, its `<style>` and `<script>`) from any game right after `<body>`, add the new folder name to its path check, and mark the game's top row with `data-pill-gap` so it shifts clear of the button. Keep the block identical in every game so the button looks and sits the same everywhere.

## Conventions
- **Every program must show a version number** on screen, e.g. a `const VERSION = "v1.0"` shown as a small label. Bump it on every change pushed (patch/minor as appropriate) and mention the new version in the commit message.
- Games must fit on an iPhone 17 Pro Max screen (about 440×800 visible in Safari) without scrolling, and also work on iPad and desktop.
- Sound must start from a user tap (iOS rule) and should work with the iPhone/iPad Silent switch on.
